01 · My contribution

I co-developed this application with team members. The public repository makes the backend available for review; the descriptions below refer to the team’s implementation, with individual module ownership still to be specified.

02 · Users & workflows

The backend supports HR and administrative work around employees, departments, roles, and leave. Its source also includes student, teaching, project, and training records.

03 · API & data model

  • Express routes, controllers, and services separate HTTP handling from application operations.
  • Sequelize associations connect employees to departments, users to roles, and roles to permissions.
  • JWT authentication loads the user and permissions; password-change gating limits access when a reset is required.
  • Leave services support filtering, pagination, employee lookup, balance checks, and status updates.
  • Joi validators and error responses are present in the API; Swagger dependencies and Docker configuration are included.

04 · Implementation decision: permissions as data

The source represents roles and permissions through a many-to-many relationship rather than only hard-coded role names. Authentication loads that permission set for downstream authorization. This supports granular access, while introducing additional policy and data-maintenance work.

This is an observed implementation choice, not a claim that I independently designed the authorization layer.

05 · Testing & delivery evidence

The repository includes API and database verification scripts plus Docker configuration. No public production deployment, reliability metric, or completed test run is claimed here. This is a backend application; an associated mobile client has not been verified.
